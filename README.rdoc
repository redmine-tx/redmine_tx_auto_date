= redmine_tx_auto_date

일감의 *실제* 작업 기록(실작업자와 작업 시작/완료/검수 시각)을 상태(stage) 전환에
맞춰 자동으로 수집하는 플러그인이다. Redmine 기본의 +start_date+ / +due_date+ 는
"계획" 값이고 +closed_on+ 은 종결 시점만 담기 때문에, "누가 언제 실제로 작업했는가"를
별도로 기록한다. 마일스톤 간트 등 다른 TX 플러그인의 기초 데이터로 쓰인다.

== 추가 컬럼 (issues 테이블)

* +begin_time+  - 작업 시작 시각 (진행/검수 단계에 처음 진입한 시점)
* +end_time+    - 작업 완료 시각 (구현끝 이상 단계에 진입한 마지막 시점)
* +confirm_time+ - 검토 시작 시각 (검수중 단계에 처음 진입한 시점)
* +worker_id+   - 실제 작업자 (담당자 핸드오프와 무관하게 작업을 수행한 사람)

이 컬럼들은 +safe_attributes+ 에 포함되지 않으며 사용자가 직접 편집할 수 없는
자동 관리 필드다.

== 동작 방식

상태 의미(stage)는 +redmine_tx_advanced_issue_status+ 의 API
(+IssueStatus.is_in_progress?+, +is_implemented?+, +is_in_review?+ 등)에 의존한다.
검수중(review)은 활성 작업 단계로 취급되며, 구현끝 판정은 stage >= IMPLEMENTED 이다.

두 가지 경로로 값을 채운다.

1. *실시간 기록* — +Issue#assign_tx_auto_date_fields+ 가 +before_save+ 콜백으로
   동작한다. 웹/REST/메일/커밋/일괄수정 등 모든 저장 경로에서 상태 전환을
   dirty tracking 으로 감지해 begin/end/confirm/worker 를 갱신한다.

2. *재계산/백필* — +Issue#update_auto_date!+ 가 저널(이력) 전체를 시간순으로
   재생하여 같은 값을 다시 계산한다. 과거 데이터 복구나 정합성 점검에 쓴다.
   (콜백을 우회한 변경이 있었거나 로직이 바뀐 경우)

두 경로는 동일한 결과를 내도록 정합을 맞춘다. 핵심 규칙:

* 작업자는 작업이 *처음 시작된 시점* 에 확정되고 이후 검수/재작업 핑퐁에도 유지된다.
* 시작시각은 최초 진행 진입, 완료시각은 마지막 구현 진입(재오픈 후 재구현 포함).
* 진행/완료 어느 단계도 아닌 상태(신규/검토중/보류/폐기, 복사본 포함)로 돌아가면
  수집값을 모두 초기화한다.

== 일감 목록(IssueQuery) 확장

+redmine_tx_0_base+ 의 +register_issue_query_columns+ DSL 로 begin_time / end_time /
confirm_time / worker 컬럼과 날짜·작업자 필터를 등록한다(init.rb 참조).
